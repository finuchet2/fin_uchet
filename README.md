# Bifintra — финансовый учёт для предпринимателей

**Bifintra** — веб-сервис для предпринимателей и самозанятых, которым необходимо вести финансовый учёт нескольких направлений деятельности в одном приложении.

Проект помогает разделять доходы и расходы по проектам, контролировать финансовые операции и анализировать результаты деятельности за выбранные периоды.

## О проекте

Предприниматели, ведущие несколько направлений бизнеса, могут сталкиваться со смешением финансовых потоков и сложностями при определении прибыльности каждого направления.

Bifintra разрабатывается как простой инструмент для ведения раздельного финансового учёта и получения наглядной информации о состоянии бизнеса.

## Основные возможности

### Финансовый учёт
- Добавление, редактирование и удаление доходов и расходов.
- Разделение операций по проектам.
- Категоризация финансовых операций.
- Учёт налоговых платежей.
- Указание фактической даты операции и периода, к которому она относится.
- Фильтрация операций по проектам и периодам.

### Финансовая аналитика
- Cash Flow — анализ движения денежных средств по датам фактических операций.
- P&L — анализ доходов и расходов за соответствующие учётные периоды.
- Расчёт финансовых показателей.
- Сравнение результатов за разные периоды.

### Пользовательский интерфейс
- Адаптивный интерфейс для компьютеров и мобильных устройств.
- Разделы проектов, операций и настроек.
- Сохранение финансовых данных в браузере.
- Поддержка PWA — возможность установки приложения на устройство.

### Авторизация
- Регистрация по электронной почте или номеру телефона.
- Вход в аккаунт.
- Хеширование паролей.
- Выдача JWT-токена для авторизованного пользователя.

## Архитектура проекта

Проект разделён на клиентскую и серверную части.

- **Frontend** отвечает за отображение интерфейса, работу с финансовыми операциями и формирование аналитических отчётов.
- **Backend** реализует серверную часть регистрации и авторизации пользователей.
- **PostgreSQL** используется для хранения учётных записей пользователей.

В текущей версии финансовые операции, проекты и категории сохраняются в браузере с помощью `localStorage`. Их полноценное хранение и обработка через серверную базу данных относятся к дальнейшему развитию проекта.

## Установка и запуск

### Требования

- Python 3.10 или выше.
- Node.js и npm.
- PostgreSQL.

### Клонирование репозитория

```bash
git clone https://github.com/finuchet2/fin_uchet.git
cd fin_uchet
```

## Запуск на Windows

### 1. Создать базу PostgreSQL

Создай в PostgreSQL пустую базу с именем `finzentra`. Если у тебя уже есть база с другим именем, укажи его в `DATABASE_URL`.

### 2. Настроить backend

Открой терминал в корневой папке проекта (там, где `requirements.txt`):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Открой корневой `.env` и обязательно замени:

```env
DATABASE_URL=postgresql+psycopg2://postgres:YOUR_PASSWORD@localhost:5432/finzentra
SECRET_KEY=REPLACE_WITH_A_LONG_RANDOM_SECRET
```

`YOUR_PASSWORD` — пароль PostgreSQL. `SECRET_KEY` — длинная случайная строка. Не отправляй `.env` в GitHub и никому не пересылай ключи.

Примени миграции из корневой папки проекта:

```powershell
alembic -c database/alembic.ini upgrade head
```

Запусти backend:

```powershell
uvicorn app.main:app --reload --port 8000
```

Проверка API: http://localhost:8000/health
Документация API: http://localhost:8000/docs

### 3. Настроить и запустить frontend

Открой второй терминал:

```powershell
cd frontend
Copy-Item .env.example .env
npm ci
npm run dev
```

Открой http://localhost:5173.

В `frontend/.env` должны быть значения:

```env
VITE_API_URL=http://localhost:8000
VITE_USE_IMPORT_API=true
```

Если меняешь `.env`, перезапусти Vite.

## Подключение GigaChat

В корневом `.env` укажи ключ авторизации GigaChat:

```env
GIGACHAT_AUTH_KEY=YOUR_GIGACHAT_AUTHORIZATION_KEY
GIGACHAT_SCOPE=GIGACHAT_API_PERS
LLM_MODEL=GigaChat
```

`GIGACHAT_AUTH_KEY` — Basic authorization key из кабинета GigaChat API. Не добавляй его в исходный код или GitHub. После изменения `.env` перезапусти backend.

В исходном классификаторе предусмотрен OpenAI-compatible fallback, если `GIGACHAT_AUTH_KEY` не задан. Для его использования отдельно заполни `LLM_API_URL`, `LLM_API_KEY` и `LLM_MODEL`. Основная настройка этой сборки — GigaChat.
